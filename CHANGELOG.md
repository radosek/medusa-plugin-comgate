# Changelog

## 0.2.4

- **Canonical status.** The webhook gets the status, price, currency and `refId` from the Comgate status API. It does not use these values from the PUSH body.
  - If the status API is not available, the webhook uses the PUSH body only if the body has the correct `secret`.
  - In all other conditions, the webhook does not change the payment.
- **Fix: webhook amount.** Comgate sends amounts in minor units. Medusa captures `data.amount` as a decimal value. Before, a PAID notification for 100 CZK captured 10000. The plugin now divides the amount by 100.
- **Anti-tamper checks.** The webhook does not change the payment if one of these checks fails. It logs an error.
  - The Comgate price and currency must be equal to the amount and currency of the payment session.
  - The Comgate `refId` must be equal to the `refId` in the PUSH body.
  - The `transId` stored on the session must be empty or equal to the PUSH `transId`.
  - A wrong `secret` now gives no change (before: `failed`).
- **Form-encoded PUSH.** The webhook reads form-encoded bodies and JSON bodies.
- **New option `proxy_key`.** The plugin sends it as the `X-Proxy-Key` header on each API call. Use it with an IPv4 relay set in `base_url`.
- **Retries.**
  - The plugin tries a call up to 4 times if a network error occurs. The wait between tries is 1 s, 2 s and 3 s.
  - The plugin does not try a call again if Comgate sent an HTTP response.
  - Refund and pre-auth capture try again only if the connection did not open. This prevents a second refund or capture.
  - Each try stops after 15 s.
- **`prepareOnly`.** The plugin sends `prepareOnly: true` when it creates a payment. The pcsmash production integration also sent it. The v2.0 documentation does not list it. A test on 2026-10-19 showed that v2.0 creates the payment with or without it.
- **Fix: refund test flag.** A refund uses the `test` flag of the original payment. Before, it used the current configuration, and Comgate returned error 1402. Sessions from before 0.2.4 use the configuration value.
- **Credentials.** The plugin removes the `secret`, the Basic token and `proxy_key` from all error messages and logs.
- **Tests.** The plugin is tested with Medusa 2.21.2. The dev dependencies changed from 2.19.0.

## 0.2.2

- **Fix: `initiatePayment` could send a non-unique `refId`.** When neither a session
  id nor an idempotency key was present it fell back to the configured `label` — a
  static value, so every such payment would have shared one `refId`. Since the webhook
  resolves the Medusa payment session by `refId`, those payments could never be
  reconciled, and could match each other. The provider now fails loudly instead. The
  Payment Module always injects `session_id`, so this was unreachable in the normal
  flow.
- `src/admin/__admin-extensions__.js`, generated by `medusa plugin:build`, is now
  gitignored.

## 0.2.1

- **Fix: refunds sent an invalid amount to Comgate.** The Payment Module passes
  `refund.raw_amount` (a raw `{ value, precision }` object) to `refundPayment`. That
  shape has no `.numeric`, so the amount became `NaN` and every admin-initiated refund
  sent a malformed request. Amounts are now normalised through Medusa's own
  `BigNumber`, which handles every `BigNumberInput` shape (number, string,
  `BigNumber`, bignumber.js instance, raw object), and an unusable amount throws
  instead of silently sending a bad request.
- Fix: `.env.example` shipped `COMGATE_TEST=1`, but the documented config checks
  `=== "true"` — that combination silently ran **production** payments. The documented
  expression now fails safe: only an explicit `false`/`0` selects production, matching
  the provider's own sandbox default.
- Tests and `scripts/` are typechecked again via `tsconfig.test.json`
  (`bun run typecheck`), fixing missing `jest`/`node` types in editors. Build output
  still excludes tests.
- Added tests covering the consumer-facing contract — the `exports` subpath, the
  `.medusa/server` build output, the `2.x` peer range, the provider identifier and the
  payment-provider methods Medusa calls by name — so a breaking change to any of them
  fails here rather than at a merchant's boot.
- `npm publish` is now gated behind the typecheck, test and plugin build.
- Bump Medusa dev dependencies to 2.18.0. `peerDependencies` stays `2.x`, so this
  installs on any Medusa 2.x host.

## 0.2.0

- **Renamed the package** from `medusa-payment-comgate-v2` to `medusa-plugin-comgate`,
  to match the Medusa Integrations Directory convention (`medusa-plugin-[name]`). The
  GitHub repository was renamed to match.
- No functional changes. Update the dependency name in `package.json`; the provider
  `resolve` path changes to `medusa-plugin-comgate/providers/comgate`, and the
  resolved provider id (`pp_comgate_comgate`) is unchanged.

## 0.1.2

- Docs: correct the return-URL placeholder behaviour. `${id}` / `${refId}` are
  substituted only in the Comgate client-portal return-URL fields; the API
  `url_paid` / `url_cancelled` / `url_pending` options are used verbatim, so an
  identifier has to be baked into those URLs by hand.

## 0.1.1

- Docs: document that Comgate uses the API return URLs verbatim, and correct the
  documented `base_url` default.
- Docs: add the Comgate logo and wordmark to the README, plus a non-affiliation
  disclaimer.

## 0.1.0

- Initial release: Comgate payment provider for **Medusa v2** using the Comgate REST v2.0 JSON API.
- Implements create, status, authorize, capture, refund, cancel, delete, retrieve, update and webhook (`getWebhookActionAndData`).
- Supports both the standard redirect flow and pre-authorization (capture/release later) via the `preauth` option.
- All six Comgate endpoints verified against the live test API.
